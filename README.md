# blox2rtl

ハードウェアのブロック図を GUI で描くツール。PySide6 製。

描いた図から Verilog を生成する(名前の `2rtl` はそこから)。
生成されるのはモジュール宣言・wire 宣言・サブモジュールのインスタンス化までで、
中身のロジックは書かない。接続の骨組みを図から起こすためのツール。

## 動かす

```powershell
pip install -r requirements.txt
python blox2rtl.py
```

テストは標準ライブラリだけで回る。

```powershell
python -m unittest discover -s tests
```

`verilog.py` のテストは PySide6 なしで動く。GUI 側のテストは PySide6 があれば
offscreen で走り、無ければスキップされる。

GUI を使わずに Verilog を出すこともできる。

```powershell
python verilog.py diagram.json out.v
```

## できること

- トップモジュールの入出力ポートを定義(ポート名・ビット幅)
- サブモジュールをブロックとして配置し、インスタンス名とポートを定義
- **同名の wire を自動接続。** 各ポートに割り当てた wire 名が一致するもの同士を結線する
- 線の太さがビット幅を表す(1bit / 2〜19bit / 20bit以上 の3段階)
- 分岐点に黒丸(ジャンクション)を描画
- ブロックとポートはグリッドスナップ、矢印キーで移動
- 表示したくない wire を非表示にできる(clk / rst など)
- JSON で保存・読込、印刷
- **Verilog 出力**(ファイル →「Verilogを出力」)

| キー | 動作 |
|---|---|
| `Ctrl+O` | ブロック図を開く |
| `Ctrl+S` | 上書き保存(保存先が未定なら名前を付けて保存へ) |
| `Ctrl+Shift+S` | 名前を付けて保存 |
| `Ctrl+P` | 印刷 |
| `Delete` | 選択したサブモジュールを削除 |
| 矢印キー | 選択した要素をグリッド1マス分動かす |

現在のファイル名はタイトルバーに出る。

## キャンバスとグリッド

配置されている要素の外接矩形に余白を足した範囲がキャンバスになる。要素を動かすと
広がるだけでなく**縮む**。`QGraphicsScene` は `sceneRect` を指定しないと過去に置いた
全アイテムの外接矩形を保持し続けて縮まないので、`updateWires()` のたびに入れ直している。

キャンバスの寸法はステータスバーに出る。範囲は破線の枠で示し、グリッドは
`GRID_SIZE`(10)ごとの細線と、10マスごとの濃い線で描く。

表示メニューでグリッドと枠をそれぞれ切り替えられる。「キャンバス全体を表示」で
全体が収まる倍率に合わせる。

**グリッドと枠は印刷に出ない。** どちらも画面上の目安なので `CustomGraphicsView` の
`drawBackground()` / `drawForeground()` で描いている。印刷が通る `scene.render()` は
ビュー側のこれらを呼ばないため、フラグで抑止しなくても紙には出ない。

### 描画するフォントはピクセルで指定する

`setPointSize()` を使ってはいけない。**ポイントは出力先の DPI で解決される**ので、
図形がシーン座標のままワールド変換だけで拡大されるのに対し、文字だけが DPI 比の
ぶん余計に大きくなる。画面 96dpi で 12px の文字が、1200dpi のプリンタでは 150px
になり、印刷したときだけ文字が図をはみ出す。

`sized_font()` を通してピクセルで指定する。ピクセル指定ならシーン座標として
扱われ、図形と同じ倍率で拡大される。`QGraphicsTextItem` を使う場合も同じで、
アイテムの font にピクセル指定のものを渡す。

グリッドを `QGraphicsItem` として置いてはいけない。`itemsBoundingRect()` に
自分自身が含まれ、キャンバスが毎回広がり続ける。

操作は、メニューの「編集」からモジュール情報とサブモジュールを編集する。
**モジュール名をダブルクリックするとモジュール情報**、ブロックをダブルクリックすると
そのインスタンス、ポートをダブルクリックすると名前を編集できる。

新しく足す要素は、今ある要素のそばに置く。サブモジュールは既存のブロックと
重ならない場所を探して置き、トップのポートはサブモジュールのかたまりの左右に付ける。
位置を固定値にすると、図が小さいときに本体から遠く離れた場所に置かれてしまう。

`scene.items()` は z 順(ほぼ挿入の逆)で返すので、ポートを扱うときは
`MainWindow.ports()` を通す。そのまま使うと並びが逆さまになる。

| 操作 | 動作 |
|---|---|
| 空白から左ドラッグ | 矩形選択 |
| 中ボタンドラッグ | 画面を掴んで動かす |
| `Ctrl` + ホイール | ポインタの位置を中心に拡大縮小 |
| `Ctrl` + `+` / `-` / `0` | 拡大 / 縮小 / 等倍 |
| `Ctrl+D` | 選択したブロックを複製(同じモジュールの別インスタンス) |
| `Delete` | 選択したブロックを削除(まとめて1回確認する) |
| 矢印キー | 選択した要素をグリッド1マス分動かす |

矩形選択の判定は `IntersectsItemShape` にしてある。`BlockItem.boundingRect()` は
ワイヤーを描くために左右へ 100 広げてあるので、`IntersectsItemBoundingRect` に
すると本体から離れたところをかすめただけで掴んでしまう。

ワイヤーは選択できない。`updateWires()` のたびに作り直すので、選んでも次の更新で
消えるうえ、矩形選択や矢印キー移動に混ざる。

## モジュールとインスタンス

**ポートの定義はモジュールが持ち、ブロックは「どのモジュールか」だけを持つ。**
同じモジュールをいくつ置いても定義は1つなので、直せば全インスタンスに効く。

ダイアログは2つに分かれる。

| | 編集するもの | 効果範囲 |
|---|---|---|
| モジュール定義 | ポートの追加・削除・ビット幅 | 全インスタンス |
| インスタンス | モジュールの選択、インスタンス名、各ポートの Wire 名 | そのブロックだけ |

インスタンス側でポート名とビット幅は読み取り専用で、打つのは Wire 名だけ。
`Tab` は Wire 名の列だけを縦に降りる。読み取り専用のセルは選択も編集もできないが、
それだけでは `Tab` の移動先から外れないので、明示的に飛ばしている。

ポート名を変えると、全インスタンスの接続がその名前に付け替わる。消えたポートの
接続は捨てる。追随できるのは、ダイアログが読み込み時の名前を各行に覚えているため。

インスタンス名は空欄なら `u_<モジュール名><連番>` で自動採番する。

定義が見つからないインスタンス(モジュールを消した後など)はブロックの色が変わる。

## ポート編集ダイアログのキー操作

ポートの入力はマウスなしで完結する。割り当てはダイアログ下部にも表示している。

| キー | 動作 |
|---|---|
| `Ctrl+I` | 入力ポートを追加(選択行の下)。すぐ名前を打てる |
| `Ctrl+O` | 出力ポートを追加(選択行の下) |
| `Tab` | 次のセルへ。行末なら次の行を追加 |
| `Enter` | 編集終了。カレントセルはその場に留まる |
| `Ctrl+Enter` | OK(確定して閉じる) |
| `Esc` | キャンセル |

行を送るのは `Tab` の役目で、`Enter` は編集を終えるだけ。`Tab` で行末まで来ると
次の行が生えるので、`Ctrl+I` を1回押したあとは `Tab` だけで何本でも続けられる。

新しい行のビット幅には `1` が入る。空のままだと `get_table_data()` がその行を
拾わず、ポートが黙って消えるため。

OK を押したとき、**一度も入力されていない行は捨てる**(`Tab` で余った末尾の行など)。
名前だけ、あるいは Wire 名だけ入っている打ちかけの行は捨てずにエラーとして示す。

### 閉じるときの検証

OK を押したときに `validate.py` で検査する。エラーがあると閉じずに、
該当するセルへカーソルが移る。

| 種別 | 内容 |
|---|---|
| エラー | ポート名が空 / モジュール名が空 |
| エラー | ビット幅が数値でない、または 1 未満 |
| エラー | ポート名の重複(入力同士・出力同士・入力と出力の間) |
| エラー | Verilog の識別子として不正(先頭が数字、`_ $` 以外の記号、予約語) |
| 警告 | サブモジュールのポートに Wire 名がない(未接続) |

未接続は作りかけでは普通に起きるので、警告どまりにして「このまま閉じますか」で
続行できる。インスタンス名の空欄は自動生成されるのでエラーにしない。

## Verilog 出力

図の内容がそのままモジュールの骨組みになる。

```verilog
// Generated by blox2rtl.

module counter (
    input  wire [7:0] din,
    output wire       dout
);

    wire [3:0] mid;

    gen u_gen (
        .en (din),
        .q  (mid)
    );

    adder u_add (
        .a (mid),
        .b (),
        .y (dout)
    );

endmodule
```

- トップの入出力ポートが module のポート宣言になる
- サブモジュールのポートに書いた Wire 名が、そのまま接続先になる(名前指定で接続)
- トップのポート名と同じ wire は宣言しない。ポート宣言が兼ねるため
- 出力順は図の見た目に合わせる。ポートは上から下、インスタンスは左から右(信号の流れ)

生成を止めない指摘は警告として出る。

- 未接続のポート、駆動元のない wire、どこにも繋がっていない wire
- 複数から駆動されている wire
- 同じ wire に異なるビット幅が指定されている(広いほうを採用する)

インスタンス名の重複のように Verilog として成立しないものは、エラーにして出力しない。

## 構成

```
blox2rtl.py       メインウィンドウと描画アイテム   Qt あり
ModuleDialog.py   ポート編集ダイアログ             Qt あり
netlist.py        データモデルと保存形式           Qt なし
verilog.py        Verilog 出力                    Qt なし
validate.py       ポート定義の検証                 Qt なし
tests/            回帰テスト
```

## データモデル

**モジュール定義とインスタンスを分けて持つ。** 同じモジュールをいくつ置いても
定義は1つで、直せば全インスタンスに効く。

```
modules    モジュール名 → ポート定義 (名前・ビット幅)
instances  モジュール名 + インスタンス名 + 位置 + 接続 (ポート名 → wire 名)
```

接続はポート名をキーにする。JSON をそのまま読めるようにするためで、ポート名の
変更に追随させるのは、編集中に行の同一性を追う側の仕事にする。

保存形式は2種類を読める。書くときは常に新形式。

| | 中身 |
|---|---|
| 形式1 (旧) | dict のリスト。サブモジュールが自分のポート定義を丸ごと持つ |
| 形式2 (新) | dict。`modules` に定義、`instances` に接続だけ |

形式1では同じモジュールを2つ置くと定義が2重に存在し、片方だけ直すと静かにずれた。
読み込み時に同名の定義をまとめ、食い違いがあれば警告する。

ファイルが増えてもルート直下のフラットな構成を保つ。
ディレクトリを切るのは、ファイルが10個を超えたときか、
pip でインストールできる配布物にするときのどちらか。

### 意識する境界

ディレクトリの分け方より、**Qt を import するかどうか**を境界として意識する。

RTL 生成は入力に対して文字列を返す処理なので、GUI を起動せずにテストできる。
そのために `verilog.py` は Qt を import せず、保存形式 (dict のリスト) だけを入力に取る。
GUI 側は `MainWindow.collectItemsData()` でその形を作り、保存と Verilog 出力の両方で使う。

`validate.py` も同じ理由で Qt を持たない。ダイアログはセルの中身を文字列のまま
渡し(`raw_rows()`)、`int()` に通す前に検査する。

`BlockItem` はポート定義を持たない。どのモジュールかという名前だけを持ち、
ポートの並びは `MainWindow.design.modules` から引く。同じモジュールのブロックは
すべて同じ定義を見る。

## 既知の問題

- `WireItem.get_uniq_x()` の `sorted_xs = mid_xs.sort()` は `None` を返しており未使用。
  縦線の重なり回避が意図どおり効いていない可能性がある
- `WireItem.instances` と `vertical_wire_lines` がクラス変数(実質グローバル)で、
  `updateWires()` の呼び出し順に依存している
